# 测试规范

## 基本原则

* 测试文件统一放在 `tests/`。
* 使用项目实际配置的测试框架和测试命令。
* 当前测试框架为 Vitest。
* 不要求编写单元测试。
* 对简单、低风险或难以稳定验证的代码，不强制新增测试。

## 验证策略

* 新功能或高风险改动根据实际情况增加有效验证。
* 测试覆盖本次修改涉及的核心行为和实际风险。
* 优先验证真实业务流程、接口行为和关键边界条件。
* 不为了覆盖率生成低价值或无法准确反映实际行为的测试。
* 仅验证本次修改涉及的功能和风险。
* 避免执行与本次任务无关的大范围测试。

## 测试结果

* 测试通过后，在没有新改动、新失败或新疑点的情况下不重复执行。
* 测试环境不完整时，不通过增加测试数量替代实际验证。
* 测试无法有效验证时，明确说明验证限制。
* 测试结果存在疑问时，明确说明疑点，不将不确定结果视为通过。

## 常用命令

```bash
npm run typecheck
npm run test
npm run build
npm run check
```

不存在的测试、Lint 或覆盖率命令不得自行写入验收标准。
